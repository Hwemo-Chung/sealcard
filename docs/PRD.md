## 0. 한 줄

**찍고, 날짜·템플릿으로 밀봉하고, 시리즈(바인더)에 꽂는다. 밀봉 후 수정 없음.**

생성(찍기)은 싸다. 제품의 핵심은 **무엇을 남길지 판단(密封)** 이다.

**후순위(한 줄)**: 밀봉 정본은 불변이다. **전시 렌더러**가 시리즈를 ‘방’으로 읽히게 하고, 같은 출력을 인앱 전시·시스템 공유·배경화면·홈 위젯(1종)으로 보낸다. 피드·등급·장수 해금은 없다. (M4 전 구현 금지 — §14)

## 1. Elon Musk 엔지니어링 5단계 적용

순서를 어기면 실패다. **4·5는 1–3 완료 후에만.**

### Step 1 — 의심하라 (Make requirements less dumb)

특히 “있어 보이는” 요구를 먼저 공격한다.

| # | 주장된 요구 | 검증 질문 | 판정 | 근거 |
|---|-------------|-----------|------|------|
| R1 | 사진은 **카드**로 저장되어야 한다 | 폴더+프레임으로  sufficiency? | **유지(조건부)** | 차별 축은 파일 형식이 아니라 **불변 단위 + 시리즈 UX**. 카드 은유 없이 불변 앨범이면 갤러리 클론. |
| R2 | **밀봉 = 수정 불가** | 사용자가 싫어하지 않나? | **유지** | 없으면 OldRoll/프레임 앱. 파기(삭제)는 별도 허용. |

R13–R16은 **코어 루프 증명(M4) 후** §14 게이트를 통과할 때만. 등급·장수 해금·소셜 피드는 삭제 유지.

### Step 2 — 제거하라 (Delete parts & processes)

“혹시 필요할지도” = 지금 넣을 이유 없음.

#### 2.1 제품에서 제거 (v1 금지 목록)

- 계정 / 로그인 / 클라우드 동기화  
- 소셜, 팔로우, 피드, 댓글, 공개 링크 갤러리  
- AI 분석, 등급, 배틀 스탯, 가챠, 미션, 광고 뽑기  
- 필름 롤·현상 대기·하루 N장 강제 제한  
- **장수·등급 기반 기능 해금** (예: N장 모이면 전시/위젯 해금, 진행률 게이지)  
- 스티커·자유 텍스트 에디터·필터 스택·빈티지 카메라 시뮬 다수  
- 사용자 템플릿 제작기, 템플릿 스토어  
- 바인더 중첩, 태그, OCR 검색, **워치**, **위젯 다종·위젯 테마 스토어**  
  - 예외(§14 P3만): Android **홈 위젯 1종**(시리즈 상설 전시). v1·M4 전에는 금지  
- 동영상 / Living Photo  
- 위치·날씨·서명 스탬프  
- 인쇄·배송  
- 온보딩 5화면, 페르소나 선택 위저드  
- 밀봉 후 편집·Undo 토스트  
- 기본 ON 갤러리 자동 저장(복제본으로 수집 의미 약화)  
- 밀봉 직후 공유/배경/위젯/전시 CTA (루프 오염)  
- 전시 화면 재bake를 카드 정본(`imagePath`)에 쓰기

#### 2.2 프로세스에서 제거

- 기능 추가 PR 전 “있으면 좋겠다” 리뷰 — **삭제 리스트 대조**만  
- 디자인 시안 N안 경쟁 — Taste 벤치: **바닥(코어 루프) 먼저**, 천장 논쟁 나중  
- 백엔드 설계 회의 — 서버 없음  
- A/B 인프라 — 사용자 10명 인터뷰·사용 로그 수기면 충분  

#### 2.3 의도적으로 남기는 제약 (부품이 아니라 법칙)

| 제약 | 이유 |
|------|------|
| 밀봉 후 이미지·날짜·템플릿 변경 UI 경로 = 0 | 제품 정의 |
| 바인더 **이동** 허용 | 정리 ≠ 개봉 |
| 카드 **파기(삭제)** 허용 | 실수·프라이버시. 복구 없음 |
| 전시·공유·배경·위젯은 **정본 비변경** (런타임/임시 파생만) | 불변 단위 유지 |
| 제시(공유/배경/위젯) 진입은 **밀봉 완료 후** 열람 경로만 | 코어 루프 비오염 |

### Step 3 — 단순화하라 (Simplify & optimize)

존재하지 말아야 할 것을 개선하지 않는다.

#### 3.1 핵심 루프 (이것만 최적화)

```
촬영 → 미리보기(최종 픽셀) → 밀봉 확인 → 바인더 선택/생성 → 그리드에 존재
```

성공 정의: **설치 후 3분 내** 카드 1장이 바인더 1개에 보인다.

#### 3.2 정보구조 (탭 2)

| 탭 | 역할 |
|----|------|
| 바인더 | 시리즈 선반 → 그리드 → 카드 상세 |
| 밀봉+ | 촬영 플로우 진입 (주 액션) |

설정: 기본 템플릿, 날짜 형식만.

#### 3.3 데이터 모델 (최소)

```
Binder { id, name, createdAt, sortKey }
Card   { id, binderId, sealedAt, templateId,
         imagePath,        // 합성 결과 (정본)
         dateFormatId,
         width, height }
Settings { defaultTemplateId, dateFormatId }
```

- 원본 RAW 별도 보관: **v1 없음** (단순화. 재밀봉 경로 자체를 안 만듦).  
- 트랜잭션: 밀봉 = 파일 write + DB insert 원자적 실패 시 롤백.

#### 3.4 템플릿

- 개수: **3** (나중에 5).  
- 내용: 프레임 + 날짜 슬롯 위치/타이포.  
- 품질 기준: “필터 장난감”이 아니라 **한 장의 인쇄물처럼 읽히는 레이아웃** (Taste: slop 금지).

#### 3.5 UX 카피 (밀봉)

- 상시 1줄: `밀봉하면 수정할 수 없습니다`  
- 모달 제목: `이 카드로 밀봉할까요?`  
- 본문: `밀봉 후에는 사진·날짜·템플릿을 바꿀 수 없습니다. 바인더는 나중에 옮길 수 있습니다.`  
- 주 버튼: `밀봉하기` / 부: `취소`  
- 2단 확인·타이핑 확인·카운트다운: **없음**  
- 파기: `이 카드를 파기할까요?` / `파기하면 복구할 수 없습니다.`

#### 3.6 페르소나 (하나만)

**B — 테마 수집가**: 시리즈 단위로 일상을 꽂는다.  
- A(하루 N장 실러), C(사건 덱) 모드는 **없음**. 카피·온보딩에서 언급 금지.

타깃 문구:  
> 아이돌 포카가 아니라, 내 일상을 시리즈로 밀봉하는 바인더.

## 2. Taste Labs 벤치마크 ([tastelabs.com](https://tastelabs.com/))

Taste Labs는 포토 카드 앱이 **아니다**.  
포지션: *subjective domains* 를 데이터·eval로 다루고, **생성 비용이 0에 가까워진 시대에 판단(taste)을 인프라로 만든다.**  
슬로건 요지: *만들기 쉬움 → 무엇을, 어떻게 훌륭하게 만들지가 병목. Kill the slop.*

이 PRD에 이식하는 규칙:

| Taste 원칙 | Sealcard 적용 |
|------------|----------------|
| Creation is cheap, judgment is rare | 셔터는 쉬움. **밀봉 버튼**이 제품. 밀봉 없는 저장 경로 없음. |
| Not just correct — *feel right* | 템플릿 3개가 “대충 프레임”이면 실패. **적은 수, 높은 바닥 품질**. |
| Raise the floor before the ceiling | 코어 루프·타이포·여백 고정 전 템플릿 마켓/AI 금지. |
| Stop debating taste → measure floor | 성공 지표는 “예쁜가 논쟁”이 아니라 **3분 밀봉·7일 재방문·바인더≥2**. |
| Codify subjective domain | “좋은 카드”를 주관에만 맡기지 않고, **불변 규칙 + 레이아웃 스펙**으로 코드화. |
| End slop | 필터 앱 기능 나열, 게이미피케이션, 제네릭 AI 그라데이션 UI **금지**. |
| Infra for eval (나중) | v1에 Taste식 eval 스택 없음. 다만 **사람이 밀봉한 결과물**이 곧 preference 신호 — 제품 자체가 judgment UI. |

**벤치 오해 금지**: Taste의 B2B eval API를 우리 백엔드에 붙이는 것이 벤치마크가 **아님**.  
벤치마크 대상은 **철학·제품 절제·품질 바닥**.

## 3. 문제 / 기회

### 문제
- 사진은 무한히 쌓이고, **남길 판단**은 앱이 돕지 않는다.  
- 프레임 앱은 공유용 예쁨, 갤러리는 검색, 포카 앱은 팬덤/게임.  
- “이 순간을 카드로 확정한다”는 **단위 행동**이 없다.

### 기회가 아닌 것 (보수)
- Exact fit 공백 ≠ 검증된 시장.  
- 대체재: 카메라 + Google Photos + OldRoll.  
- 근접: tin(포카), Lumhaa(seal 의식), PhotoCard Elan(사진→카드 게임, 스케일 미검증).

### 기회 (좁은 쐐기)
동시에: **불변 밀봉 + 날짜 정체성 + 시리즈 바인더 + 비게임**.  
이 네 가지를 한 루프로 제공하는 1등 제품은 조사 시점에 불명 — **수요는 미검증**.

## 4. 목표 / 비목표

### Goals (v1)
1. 밀봉 루프 완료 가능 (오프라인).  
2. 밀봉 카드 변조 UI 없음 (자동 테스트로 고정).  
3. 바인더 단위 열람이 기본 뷰.  
4. dogfood 10명 기준 학습 문서 1장.

### Non-goals (v1)

## 10. 기술 제약 (가속용 기본값)

**결정 (2026-08-05, 사용자)**: 구현은 **TypeScript + 네이티브 모듈(Expo/React Native)**.  
Kotlin Compose 풀 네이티브는 루프 검증 후 필요 시 포팅. 병목은 제품이지 브리지 성능이 아님.

- TypeScript strict, Expo SDK (Android-first)  
- 카메라: `expo-camera` / 파일: `expo-file-system` / 합성 캡처: `react-native-view-shot`  
- 메타: AsyncStorage · 카드 정본: app document 디렉터리 JPEG  
- 네트워크 permission **불필요**가 목표 (광고 SDK 금지)  
- 접근성: 밀봉/파기 버튼 accessibilityLabel 필수  
- 코드: `mobile/`  
- §14 배경·위젯: **dev client / 네이티브 모듈** 전제 가능. 순수 Expo Go only 가정 폐기 각오. iOS 위젯·iOS 배경 API = R12와 같이 1st 기각

## 14. 전시 · 제시 채널 (post-M4 Icebox)

> **상태**: Icebox. M4 게이트 전 구현 PR = 거절.  
> **철학**: 전시는 시리즈 **열람의 두 번째 표면**이다. 장수 해금 콘텐츠가 아니다.  
> **시각 레퍼런스**: 저장소 루트 프레임 예제(흰 벽·스포트·블랙 프레임·흰 매트·월 라벨). 기능 해금 조건 아님.

### 14.1 한 줄 아키텍처

```
밀봉 정본 imagePath (불변)
        │
        ▼
 Presentation Renderer  (전시 스테이지와 동일 스펙)
        │
        ├── 인앱 전시 모드     (P0)
        ├── 시스템 공유 시트   (P1)
        ├── 배경화면           (P2)
        └── 홈 위젯 1종        (P3)
```

채널마다 UI·권한·해상도만 다르다. 렌더러 중복 구현 금지.

### 14.2 고정 규칙 (악마 검증 후 확정)

| # | 규칙 |
|---|------|
| E1 | **잠금 없음**. 바인더 카드 ≥1 이면 전시 모드 진입. 전역/바인더 N장 게이트 없음. |
| E2 | **자동 장수 배지·상설 상태머신 없음** (8장/30장 해금·진행률 UI 금지). 홈 위젯·배경이 “상설”의 물리 표현. |
| E3 | **스키마 변경 0** 이 P0–P2 목표. P3만 Settings에 위젯 포인터 허용. |
| E4 | 전시 프레임 프리셋 **1종** (얇은 블랙 + 흰 매트). 밀봉 템플릿별 전시 액자 분기 금지 (이중 액자 방지). |
| E5 | 소품(화분 등)·3D 룸·파티클 **P0 금지**. 벽·라이트·프레임·월 라벨만. |
| E6 | 순회 정렬 = `sealedAt` 한 방향만 (P0). `wallOrder` / `wallMounted` 는 요청 증거 전 금지. |
| E7 | IA: 전시 전용 탭 금지. 바인더 상세 `mode: grid \| wall` 권장. |
| E8 | 밀봉 플로우·밀봉 직후 시트에 전시/공유/배경/위젯 **진입점 없음**. |
| E9 | 파생 이미지 = 캐시/임시 파일. DB 카드 레코드·`imagePath` 에 저장 금지. |
| E10 | 워터마크·앱 로고 **기본 OFF**. 강제 브랜드 슬레이트 금지. |
| E11 | 위젯 랜덤·“오늘의 카드”·시간 순환 슬라이드쇼 금지. |
| E12 | 시각 바닥 미달 = 기능 미머지 (Taste: raise the floor). |

### 14.3 Presentation Renderer

| 항목 | 스펙 |
|------|------|
| 입력 | 카드 1 + 선택적 바인더명 |
| 레이아웃 | 갤러리 방: 벽 톤 + 작품(정본 전체) + 블랙 프레임 + 흰 매트 + 월 라벨(제목·날짜) |
| 정본 관계 | 밀봉 템플릿이 bake된 `imagePath` 를 **통째로** 매트 안에 배치. 정본 재합성 없음 |
| 프로필 | `screen` · `share`(짧은 변 ~1080–1440) · `wallpaper`(디스플레이 해상도≥) · `widget`(셀 밀도) |

### 14.4 페이즈

| Phase | 내용 | 스키마 | 완료 정의(요약) |
|-------|------|--------|-----------------|
| **P0** | 바인더 `그리드 \| 전시` + Renderer `screen` | 0 | 카드≥1 진입; 스와이프 순회; 모드 전환 전후 정본 필드 불변; §14.5 시각 QA |
| **P1** | Renderer → **시스템 공유 시트** | 0 | 임시 JPEG; 피드 UI 0; 기본=전시 구도(옵션으로 정본 only 가능) |
| **P2** | Renderer → **배경 미리보기 + 설정** | 0 | 크롭 정책 1; 홈/잠금/둘 다; OEM 실패 시 “저장 후 직접 설정” fallback |
| **P3** | **Android 위젯 1종** | Settings 2필드 | 바인더 또는 고정 카드; 밀봉·파기·이동 시 갱신; 탭→해당 바인더 전시 모드 |

**역순 금지**: 위젯/공유를 P0 렌더러·시각 QA 없이 먼저 붙이지 않는다.

### 14.5 시각 QA (P0 머지 게이트)

루트 프레임 예제 대비 체크 (전부 통과):

1. 한 장 집중, 큰 벽 여백 (그리드 확대 수준이 아님)  
2. 얇은 어두운 프레임 + 넓은 밝은 매트  
3. 상단 조명 힌트(과장 파티클 없음)  
4. 월 라벨: 바인더명 + 밀봉 날짜(기존 `dateFormatId`)  
5. 크롬 최소 — OS 갤러리 풀스크린과 구별됨  

### 14.6 데이터 (P3만 추가 허용)

```
Settings {
  defaultTemplateId, dateFormatId,   // 기존
  widgetBinderId?,   // null = 위젯 미설정
  widgetCardId?      // null = 해당 바인더 최신 1장
}
```

카드 파기 시 포인터 null/fallback. 공유·배경은 DB 불필요.

### 14.7 UX 진입

- 바인더 상세: `그리드 | 전시`  
- 카드 상세 또는 전시 모드 메뉴 **제시**: `이미지 공유` · `배경화면으로` · `위젯에 고정…`  
- 미분류: 전시 뷰 허용. 위젯 기본 대상으로 권장하지 않음(시리즈 없음)

### 14.8 성공 / 실패 (post-M4)

| 건강 | 불건강 |
|------|--------|
| 밀봉·시리즈 지표 유지 | 공유만 늘고 밀봉 정체 |
| 전시→공유는 보조 전환 | 공유를 주 KPI로 승격 |
| 위젯 탭 후 앱 전시 진입 | 위젯만 보고 앱 미진입 |
| 불변 테스트 0 위반 | 파생본이 `imagePath` 로 치환 |

### 14.9 명시적 기각 (§14 범위 안에서도)

- 총 카드/바인더 N장 해금, 상설 자동 배지, 진행률 `12/30`

- 스토리 비율 전용 에디터, 자유 크롭·스티커  
- 위젯 다종, 워치, 일일 랜덤, 배경 다장 슬라이드쇼
