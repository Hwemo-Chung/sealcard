## 4. 빌드

- vc4는 저장소 밖에서 서명되었다. 서명자는 `CN=, OU=, O=, L=, ST=, C=US`, SHA-256 `AD:53:52:D0:7F:4E:8B:91:45:72:66:D7:90:18:CC:A5:08:24:A4:F0:9F:41:F2:79:54:99:03:80:04:F3:32:21`, 서명 파일 `META-INF/E4B3AC6F.RSA`(Signflinger), VCS 정보 `NO_SUPPORTED_VCS_FOUND`이다.
- 저장소에 업로드 키스토어가 없다. 워크트리의 `android/`는 2026-08-07 prebuild 산출물로 `versionCode 1`이고 release가 `debug.keystore`(SHA-256 `FA:C6:…:3B:9C`)로 서명된다. 문서화된 빌드 경로는 EAS(`eas.json`: `appVersionSource: remote`, `autoIncrement`)뿐이다.
- 산출물만으로는 EAS 클라우드 빌드와 `eas build --local`을 구별할 수 없다[중간]. 두 방식 모두 EAS에 저장된 자격 증명을 쓰므로 로그인이 필요하다. 서명 파일 이름 `E4B3AC6F`는 키 별칭의 앞 8자를 대문자로 바꾼 값으로 추정한다[중간].
- 1.0.2(2026-11-12): `app.json` `expo.version`을 `1.0.2`로 올렸다. versionCode는 EAS 원격 `autoIncrement`이므로 건드리지 않았다(`app.json`에 versionCode 없음). 이번 빌드에는 로컬 네이티브 모듈 `modules/sealcard-geocoder`(U14)가 처음 들어간다. vc10 AAB에서는 루트 `.gitignore`의 `android/` 때문에 모듈이 빠졌다. 그래서 루트 규칙을 `/mobile/android/`로 고쳤다. 다음 빌드(vc11)는 U14의 릴리스 게이트 두 가지를 모두 통과해야 제출한다: 빌드 로그의 `:sealcard-geocoder:compileReleaseKotlin`, AAB dex의 `SealcardGeocoder`. dex 확인 명령은 AAB로는 돌려 보지 않았다. 로컬 APK `mobile/sealcard-production.apk`(모듈 이전 빌드)에 같은 파이프라인을 돌리면(APK는 경로 `classes*.dex`) `ExpoLocation` 1, `SealcardGeocoder` 0이 나온다. AAB에서는 경로가 `base/dex/classes*.dex`다. 이 워크트리에서는 빌드하지 않았다.
- 따라서 이번 작업은 코드와 테스트까지만 한다. vc5/1.0.1 빌드에 필요한 것: (1) SHA-256 `AD:53:…:32:21` 업로드 키스토어(별칭·비밀번호 포함)이나 그 키로 서명하는 EAS 빌드, (2) `app.json`의 `expo.version`을 `1.0.1`로 변경(설정 화면 버전 표시도 이 값을 읽음), (3) versionCode 5(EAS 원격 카운터 `autoIncrement`가 현재 4인지는 로그인 없이 확인할 수 없음).
